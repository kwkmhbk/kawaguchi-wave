# 川口元郷駅「お客さんの波」カウントダウン

埼玉高速鉄道 川口元郷駅で電車を降りたお客さんが店に来る「波」が、あと何秒で来るかを iPhone に表示する自分用のWebアプリです。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | Webアプリ本体。時刻表データも中に埋め込まれている |
| `extract.js` | 時刻表JSONから川口元郷の到着時刻を抜き出し、`index.html` に埋め込むスクリプト |
| `seconds-correction.json` | 秒補正テーブル（平日22〜24時の列車の、川口元郷に着く秒数の推定値） |
| `README.md` | この説明 |

## 時刻表の更新（ダイヤ改正のとき）

PC（Node.js が必要）でこのフォルダを開き、次を実行するだけです。

```
node extract.js
```

- GitHub の Mini Tokyo 3D から最新の時刻表をダウンロードし、`index.html` の中のデータ部分だけを書き換えます。
- 方向別・平日/土休日別の本数と始発・最終の時刻が表示されるので、公式時刻表と見比べてください。
- 行き先に知らない駅が出てきたら警告が出ます。`extract.js` の `DEST_NAMES` に日本語名を書き足してください。
- Mini Tokyo 3D 側のデータ更新はダイヤ改正日より遅れることがあります。
- 書き換えたあとは、置き場所（GitHub Pages など）にもう一度アップロードしてください。

## 仕組み

- 波の到着時刻 ＝ 推定した到着時刻＋歩行時間（詳しくは「到着秒の推定」を参照）。歩行時間とオフセットは、同じホームなので上り・下り共通です。
- iPhone SE（第3世代）の**横向き**（667×375）を基準にした画面です。縦向きでも表示はできますが、文字は小さくなります。
- 画面は駅の発車標風で、左に上り（赤羽岩淵方面）、右に下り（浦和美園方面）を表示します（設定で左右を入れ替え可）。
- 残りが0秒になると「到着」と表示して 0, 1, 2… とカウントアップし、設定した秒数（初期値60秒）まで数えたら次の波に切り替わります。
- 各列の一番上の「前駅 → 当駅 → 店」は、今どこにいるかの表示です。前駅を出る前は電車が前駅のそばに止まり、前駅→当駅は電車のアイコンが、当駅→店は人のアイコンが時間に合わせて動きます。店に着くと人のアイコンが赤くなります（前駅を出る時刻は、推定の到着時刻から走行時間を引いた目安）。
- カウントダウンは「お客さんが店に着くまで」の秒数です。位置表示の「当駅」「店」の上の小さな時刻（分:秒）は、電車が駅に着く時刻（推定）と、お客さんが店に着く時刻です。それぞれの時刻を過ぎると赤に変わります。
- 各列の下の一覧（次以降の電車）は、左に時刻、右にその時刻までの残り時間を出します。初期値は1行表示で、指でスライドすると先の時刻（40本先まで）を確認できます。スライドしたあと10秒間触らなければ、一番上に戻ります。設定で2行表示にもできます（1行のほうがカウントの数字が大きくなります）。
- 画面をタッチすると表示を切り替えられます（状態は保存されます。切り替えても上と下の高さは変わりません）。
  - 一覧より上（カウントの部分）: カウントを「秒」→「分:秒」（1時間以上は「時:分:秒」）→「分」→「秒」…の順に切り替え。「分」表示は秒を切り捨て、1分未満は「あと1分以内」、店に着く時刻になったら「到着」
  - 一覧の左半分: 時刻を「駅着」⇔「店着」
  - 一覧の右半分: 残り時間を「秒」→「分:秒」→「分（秒は切り捨て）」→「秒」…の順に切り替え
  - 初期表示は、カウントも一覧の残り時間も「あと●分」、一覧の時刻は「店着」です。
- 表示するのはその日（運行日）の電車だけです。その日の最後の電車の到着後カウントが終わると、その列は「本日の運行は終了しました」「終了」の表示になります。朝4時に運行日が切り替わると、その日の始発からの表示に戻ります。
- 設定画面は、左上の「川口元郷」の文字を押すと開きます。
- 設定画面のオフセットは ▲▼ ボタンで1秒ずつ変えます（押し続けると速く変わります）。
- 遅延情報の取得状況（APIキー未設定・取得できない・最後に確認した時刻）とデータ提供元は、設定画面に表示します。
- 0時台の電車（時刻表では `00:xx`）は前日のダイヤの続きとして扱います。4時より前は前日の運行日とみなします。
- 土曜・日曜・祝日・年末年始（12/30〜1/3）は土休日ダイヤを使います。年末年始は特別ダイヤになる場合がありますが、今は土休日ダイヤとして扱っています。
- 祝日は 2026年と2027年の分だけ入っています。2028年になる前に、`index.html` の `HOLIDAYS` に書き足してください（期限を過ぎると画面に「祝日リスト要更新」と出ます）。

## 到着秒の推定

時刻表の時刻は分単位（秒は切り捨て）なので、川口元郷に着く秒数を列車ごとに推定しています。

- 波の時刻 ＝ 推定した到着時刻（秒まで）＋ 歩行時間（電車が到着してから、お客さんが店に着くまでの時間。設定画面の▲▼で変更可、上り・下り共通、初期値100秒）。
- 推定できなかった列車だけは「到着分（秒00）＋ オフセット（上り・下り共通、初期値60秒）」です（今の時刻表では該当なし）。

### 自動推定（`extract.js`）

`node extract.js` を実行すると、Mini Tokyo 3D の時刻表にある前後の駅（赤羽岩淵・南鳩ケ谷）の着発時刻から、全列車（平日・土休日）の到着秒を推定します。

- 前の駅の発車分・川口元郷の到着分・発車分・次の駅の到着分のすべてと矛盾しない到着秒の範囲を求め、その真ん中を使います。
- 仮の値: 赤羽岩淵→川口元郷 150秒、川口元郷→赤羽岩淵 165秒、南鳩ケ谷⇔川口元郷 135秒、川口元郷での停車 30秒（`extract.js` の `EST` で変更可）。
- 停車30秒では計算が合わない列車（下りで「赤羽岩淵から3分で到着・1分停車」の並びの約100本）は、停車を30〜60秒の幅で計算します。
- ダイヤ改正のときも、実行し直せば自動で計算し直されます。
- 推定は仮の値に左右される目安です（境目が15秒ほど動きます）。

### 秒補正テーブル（`seconds-correction.json`）

自動推定より優先して使う、手で指定する到着秒の表です。今は平日22:00〜24:00の28本について、Yahoo!乗換案内の各列車ページをもとにした推定値が入っています（自動推定と同じ値）。

- 平日ダイヤの列車と「方向（`Outbound` / `Inbound`）＋到着分（`arr`）」で照合し、一致した列車には `est` を使います。
- 照合できなかった行は、実行時に一覧で表示されます。特定日だけ走る列車がその日のデータに無い場合などは、照合されなくても問題ありません。
- 推定に使った前後の駅の時刻と推定範囲は、出典の転載にあたるため公開せず、このPCの `seconds-correction-detail.json` にだけ残しています（`.gitignore` でGitHubに上げない設定）。
- **実測したら**: `est` を `"22:01:45"` の形で書き換え、`node extract.js` を実行し直してから公開し直してください。
- 推定は仮の走行時間・停車時間に左右される目安です（境目が15秒ほど動きます）。**ダイヤ改正があったら使えなくなる**ので、作り直すか中身を `[]` にしてください。

## 遅延の自動検知

- 東京メトロの運行情報（ODPT API）から南北線の状況を、画面に表示されている間だけ3分ごとに取得します。
- 平常でなければ、カウントダウンがグレーになり、上の帯に「南北線 遅延中・予測は目安」が出ます。これをタップすると運行情報の文章が開きます。予測時刻はずらしません。
- APIキーは設定画面（左上の「川口元郷」を押すと開く）から入力します。iPhone の中（localStorage）にだけ保存され、HTMLには書き込まれません。

### 限界

- 東京メトロの運行情報は5分以上の遅れが対象なので、それより小さい遅れは検知できません。
- 埼玉高速鉄道の区間だけで起きた遅れは、南北線の情報に出ないことがあります。
- 埼玉高速鉄道の公式運行情報（15分以上の遅れを掲載）は、ブラウザから直接読み込めない作りのため使っていません。

## 置き場所の比較

Wake Lock などを使うため、HTTPS で開ける場所に置く必要があります。

| 方法 | 手間 | 費用 | 公開範囲 |
|---|---|---|---|
| **GitHub Pages**（おすすめ） | GitHubのアカウントが必要。更新は `git push` だけ | 無料 | 無料プランでは公開リポジトリが必要なので、コードもURLも誰でも見られる（URLを知らなければ普通は見つからない） |
| Cloudflare Pages / Netlify | アカウントが必要。ファイルをブラウザでドラッグ＆ドロップして公開できる | 無料 | URLを知っていれば誰でも開ける。コード置き場は非公開にできる |
| iPhone 内のファイルを直接開く | — | — | HTTPS にならず、ホーム画面アプリとしてもうまく動かないため不可 |

どの方法でも APIキーはHTMLに入っていないので、公開してもキーは見られません。

## GitHub Pages での公開手順（PC）

※ すでに公開済み。別の場所に作り直すときの手順として残している。

1. GitHub で新しい公開リポジトリを作る（例: `kawaguchi-wave`）。
2. このフォルダで次を実行する。
   ```
   git init
   git add index.html extract.js README.md
   git commit -m "最初の版"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/kawaguchi-wave.git
   git push -u origin main
   ```
3. GitHub のリポジトリ画面で **Settings → Pages** を開き、Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして保存する。
4. 数分後に `https://<ユーザー名>.github.io/kawaguchi-wave/` で開けるようになる。

時刻表を更新したときは、`node extract.js` のあとに次を実行します。

```
git commit -am "時刻表を更新"
git push
```

## iPhone での使い方

1. iPhone の **Safari** で上のURLを開く。
2. 下の共有ボタン（四角から矢印が出ているアイコン）→「**ホーム画面に追加**」→「追加」。
3. ホーム画面の「波カウント」から起動する。
4. 左上の「川口元郷」を押して設定画面を開き、歩行時間（秒）と ODPT の APIキーを入力して「保存」。

画面を表示している間は、自動で画面が消えないようにしています（iOS 16.4 以降。低電力モードでは効かないことがあります）。

## 動作確認用のデバッグ機能

URL の最後に `?debug` を付けて開くと、画面の下にデバッグ用の欄が出ます。

- 好きな日時に時計を合わせられます（平日朝・土曜・祝日・日付またぎ・終電後・年末のボタンあり）。
- 遅延情報を「平常」「遅延」「取得失敗」の模擬データに切り替えられます。

## データの提供元

- 時刻表: Mini Tokyo 3D（https://github.com/nagix/mini-tokyo-3d）が公開しているデータ。元は公共交通オープンデータセンター（ODPT）のオープンデータ。
- 運行情報: 公共交通オープンデータセンター（ODPT）の東京メトロ運行情報。
- データの正確さは保証されていません。目安として使ってください。
