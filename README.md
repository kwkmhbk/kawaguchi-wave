# 元郷 人波時計（川口元郷駅「お客さんの波」カウントダウン）

埼玉高速鉄道 川口元郷駅で電車を降りたお客さんが店に来る「波」が、あと何秒で来るかを iPhone に表示する自分用のWebアプリです。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | Webアプリ本体。時刻表データも中に埋め込まれている |
| `extract.js` | 時刻表JSONから川口元郷の到着時刻を抜き出し、`index.html` に埋め込むスクリプト |
| `watch.js` | ダイヤ改正の見張り。南北線の時刻表と Mini Tokyo 3D の時刻表が変わったかを調べる |
| `.github/workflows/timetable-watch.yml` | 見張りを GitHub で毎朝実行し、変化があれば Issue を作る設定 |
| `relay/worker.js` / `relay/wrangler.toml` | 遅延情報の中継サーバー（Cloudflare Workers）。ODPT の APIキーはここにだけ預ける |
| `apple-touch-icon.png` / `favicon.png` | ホーム画面のアイコン（180×180）とブラウザのタブのアイコン |
| `manifest.webmanifest` / `icon-192.png` / `icon-512.png` | Android などでホーム画面からアプリとして（全画面で）開くための情報とアイコン |
| `sw.js` | サービスワーカー。Android の Chrome でアプリとしてインストールできるようにするためのもの。毎回ネットから最新を取り、つながらないときだけ保存しておいた版を出す |
| `img/ios-step1〜4.jpg` | iPhone の Safari でのインストール手順の画像（実機の画面を切り取り、押す場所を赤枠で囲んだもの。状態表示とキーボードは含めない） |
| `README.md` | この説明 |

## 時刻表の更新（ダイヤ改正のとき）

PC（Node.js が必要）でこのフォルダを開き、次を実行するだけです。

```
node extract.js
```

- GitHub の Mini Tokyo 3D から最新の時刻表をダウンロードし、`index.html` の中のデータ部分だけを書き換えます。
- 方向別・平日/土休日別の本数と始発・最終の時刻が表示されるので、公式時刻表と見比べてください。
- 行き先に知らない駅が出てきたら警告が出ます。`extract.js` の `DEST_NAMES` に日本語名を書き足してください。
- Mini Tokyo 3D 側のデータ更新はダイヤ改正日より遅れることがあります。
- 書き換えたあとは、置き場所（GitHub Pages など）にもう一度アップロードしてください。
- 更新を終えたら `node watch.js --save` で南北線の印をアプリに書き込み直してください。公開すると、アプリの「時刻表 変更の可能性」の表示が消えます（下の「ダイヤ改正の見張り」を参照）。

## 仕組み

- 波の到着時刻 ＝ 推定した到着時刻＋歩行時間（詳しくは「到着秒の推定」を参照）。歩行時間と前駅の発車調整は、上り・下り共通です。
- iPhone SE（第3世代）の**横向き**（667×375）を基準にした画面です。縦向きのときは、上り・下りを上下に並べて表示します。
- 画面は駅の発車標風で、左に上り（赤羽岩淵方面）、右に下り（浦和美園方面）を表示します（設定の「上り・下りを入れ替える」で左右を入れ替え可。縦画面では上下）。
- 残りが0秒になると「到着」と表示して 0, 1, 2… とカウントアップし、設定した秒数（初期値70秒）まで数えたら次の波に切り替わります。「到着」の文字は点滅せず、赤で点灯したままです。
- 各列の一番上の「前駅 → 当駅 → 店」は、今どこにいるかの表示です。前駅を出る前は電車が「前駅」の左（画面の端）に止まり、前駅→当駅は電車のアイコンが、当駅→店は人のアイコンが時間に合わせて動きます。店に着くと、人は「店」の右（画面の端）に立ちます。「当駅」「店」の上の時刻は、着いたら「到着」に変わります。点滅はしません（前駅を出る時刻は、推定の到着時刻から走行時間を引いた目安に、設定の「前駅の発車調整」を足したもの）。
- カウントダウンは「お客さんが店に着くまで」の秒数です。位置表示の「当駅」「店」の上の小さな時刻（分:秒）は、電車が駅に着く時刻（推定）と、お客さんが店に着く時刻です。それぞれの時刻を過ぎると赤に変わります。
- 各列の下の一覧（次以降の電車）は、左に時刻、右にその時刻までの残り時間を出します。1行表示で、指でスライドすると先の時刻（40本先まで）を確認できます。スライドしたあと10秒間触らなければ、一番上に戻ります。一覧の時刻を「駅着」と「店着」のどちらにするかは、設定画面の「一覧の時刻」で選びます（初期値は店着）。
- 画面をタッチすると表示を切り替えられます（状態は保存されます。切り替えても上と下の高さは変わりません）。
  - 一覧より上（カウントの部分）: カウントを「秒」→「分:秒」（1時間以上は「時:分:秒」）→「分」→「秒」…の順に切り替え。「分」表示は秒を切り上げ（「あと4分」→「あと3分」→「あと2分」→「あと1分以内」）、店に着く時刻になったら「到着」
  - 一覧の右半分: 残り時間を「秒」→「分:秒」→「分（秒は切り上げ）」→「秒」…の順に切り替え
  - 初期表示は、カウントも一覧の残り時間も「あと●分」、一覧の時刻は「店着」です。
- 表示するのはその日（運行日）の電車だけです。その日の最後の電車の到着後カウントが終わると、その列は「本日の運行は終了しました」「終了」の表示になります。朝4時に運行日が切り替わると、その日の始発からの表示に戻ります。
- 設定画面は、左上の「川口元郷」の文字を押すと開きます。
- 設定画面の歩行時間・到着後カウント・前駅の発車調整は ▲▼ ボタンで1秒ずつ変えます（押し続けると速く変わります）。
- 「前駅の発車調整」は、位置表示の「前駅」の上の時刻と、電車のアイコンが動き出す時刻をずらします（初期値0秒、−60〜＋60秒。＋で遅く、−で早く）。カウントや「当駅」「店」の時刻は変わりません。
- 設定画面の「その他」にある「初期値に戻す」の「戻す」ボタンを押すと、設定の値がアプリの初期値（歩行時間120秒・到着後カウント70秒・前駅の発車調整0秒・上り・下りの入れ替えオフ・一覧の時刻は店着）に戻ります。本体画面をタップして切り替えるカウントや一覧の残り時間の表示も初期値に戻ります。「保存」を押すと反映され、「キャンセル」で取り消せます。
- 設定画面の「アプリ」にある「最新版に更新」の「更新」ボタンを押すと、公開されている最新の版で読み込み直します。今の版は、その下の「バージョン」（公開した日時）で確かめられます。
- 遅延情報の取得状況（APIキー未設定・取得できない・最後に確認した時刻）とデータ提供元は、設定画面に表示します。
- 0時台の電車（時刻表では `00:xx`）は前日のダイヤの続きとして扱います。4時より前は前日の運行日とみなします。
- 土曜・日曜・祝日・年末年始（12/30〜1/3）は土休日ダイヤを使います。年末年始は特別ダイヤになる場合がありますが、今は土休日ダイヤとして扱っています。
- 祝日は 2026年と2027年の分だけ入っています。2028年になる前に、`index.html` の `HOLIDAYS` に書き足してください（期限を過ぎると画面に「祝日リスト要更新」と出ます）。

## 到着秒の推定

時刻表の時刻は分単位（秒は切り捨て）なので、川口元郷に着く秒数を列車ごとに推定しています。

- 波の時刻 ＝ 推定した到着時刻（秒まで）＋ 歩行時間（電車が到着してから、お客さんが店に着くまでの時間。設定画面の▲▼で変更可、上り・下り共通、初期値120秒）。
- 推定できなかった列車だけは「到着分（秒00）＋ 60秒」です（`index.html` の `UNKNOWN_SEC_OFFSET`。今の時刻表では該当なしのため、設定画面からは外した）。

### 自動推定（`extract.js`）

`node extract.js` を実行すると、Mini Tokyo 3D の時刻表にある前後の駅（赤羽岩淵・南鳩ケ谷）の着発時刻から、全列車（平日・土休日）の到着秒を推定します。計算は PC で実行したときに1回だけ行い、結果を `index.html` に書き込みます（アプリは書き込まれた秒数を読むだけ）。

全列車をこの1つの方法で推定しています（以前は平日22〜24時の28本だけ、Yahoo!乗換案内をもとに手で指定した秒補正テーブルを使っていたが、2026-11-27 にやめて一本化した。値は自動推定と同じだった）。

- 前の駅の発車分・川口元郷の到着分・発車分・次の駅の到着分のすべてと矛盾しない到着秒の範囲を求め、その真ん中を使います。
- 仮の値: 赤羽岩淵→川口元郷 150秒、川口元郷→赤羽岩淵 165秒、南鳩ケ谷⇔川口元郷 135秒、川口元郷での停車 30秒（`extract.js` の `EST` で変更可）。
- 停車30秒では計算が合わない列車（下りで「赤羽岩淵から3分で到着・1分停車」の並びの約100本）は、停車を30〜60秒の幅で計算します。
- ダイヤ改正のときも、実行し直せば自動で計算し直されます。
- 推定は仮の値に左右される目安です（境目が15秒ほど動きます）。仮の値は AI が決めたもので、実測ではありません。

## ダイヤ改正の見張り

GitHub が毎朝6時（日本時間）に `node watch.js` を実行し、次の2つを調べます。変化があれば、リポジトリに Issue「時刻表の変化を検知しました（ダイヤ改正の可能性）」を作り、登録メールに通知が届きます。

| 調べるもの | 方法 | 分かること |
|---|---|---|
| 南北線（赤羽岩淵駅）の時刻表 | 中継サーバー経由で ODPT から読み、`index.html` の `TT_WATCH`（今の時刻表を入れたときの印）と比べる | 南北線と埼玉高速鉄道は直通運転なので、ダイヤ改正はほぼ同じ日。いちばん早く気づける |
| Mini Tokyo 3D の時刻表 | `node extract.js --check` で、アプリに入っている時刻表と比べる | 時刻表を更新できる合図（前回のダイヤ改正では4日遅れで更新された） |

- 埼玉高速鉄道は ODPT にデータを出していないため、南北線で代わりに見張っています。
- Issue が開いたままなら、内容が変わったときだけ追記します（毎日同じ通知は来ません）。対応を終えたら Issue を閉じてください。
- 対応の手順: 公式のお知らせを確かめる → Mini Tokyo 3D が更新されたら `node extract.js` → `node watch.js --save` → 公開。

### アプリの画面での表示

- アプリも、開いたときと3時間ごとに（画面に表示されている間だけ）中継サーバーから南北線の時刻表の印を読み、`TT_WATCH` と比べます。
- 違っていたら、上の帯に枠線だけの「時刻表 変更の可能性」（縦画面では「時刻表」）を出します。押すと説明が開きます。カウントは今の時刻表のままです。
- 遅延中のときは「遅延中」を優先して出し、こちらは隠します。印を取れなかったときは何も出しません（30分後にもう一度試します）。
- 時刻表を更新して `node watch.js --save` で印を書き込み、公開すると消えます。
- 設定 →「動作の確認」の「時刻表の変化」で「変化あり」を選ぶと、見た目を確かめられます（アプリを開き直すと元に戻ります）。そこに、実際に確かめた結果と時刻も出ます。
- PC でも `node watch.js` で同じ確認ができます。GitHub の Actions 画面の「ダイヤ改正の見張り」→「Run workflow」で、すぐに実行することもできます。そのとき「テスト」にチェックを入れると、変化がなくても【テスト】の Issue を作るので、通知メールが届くかを確かめられます。
- 見張りが失敗したとき（中継サーバーや ODPT につながらない など）は、GitHub から失敗のメールが届きます。
- **注意**: 公開リポジトリで60日間 push がないと、GitHub が毎日の実行を自動で止めます。止まる前に GitHub からメールが来るので、Actions 画面で「Enable workflow」を押して再開してください。
- 中継サーバーの `/timetable-watch` は、ODPT の南北線・赤羽岩淵駅の駅時刻表から印を作って返します（1時間ためておく）。時刻・行き先・種別・方向・曜日区分だけから作るので、データの取得日などが変わっても印は変わりません。

## 遅延の自動検知

- 東京メトロの運行情報（ODPT API）から南北線の状況を、画面に表示されている間だけ3分ごとに取得します。
- 平常でなければ、カウントダウンがグレーになり、上の帯に「南北線 遅延中・予測は目安」が出ます。これをタップすると運行情報の文章が開きます。予測時刻はずらしません。
- 運行情報は、アプリから直接ではなく、中継サーバー（Cloudflare Workers）を通して取ります。ODPT の APIキーは中継サーバーにだけ預けてあるので、端末ごとにキーを入力する必要はなく、公開しているHTMLやGitHubからキーが見えることもありません。
- 中継サーバーは同じ結果を60秒ためておくので、端末が何台あっても ODPT への問い合わせは1分に1回までです。
- 中継サーバーは、公開先（`https://kwkmhbk.github.io`）のページからの読み込みだけを受け付けます。
- `index.html` の `RELAY_URL` が空欄のあいだは、遅延検知は止まります。

### 限界

- 東京メトロの運行情報は5分以上の遅れが対象なので、それより小さい遅れは検知できません。
- 埼玉高速鉄道の区間だけで起きた遅れは、南北線の情報に出ないことがあります。
- 埼玉高速鉄道の公式運行情報（15分以上の遅れを掲載）は、ブラウザから直接読み込めない作りのため使っていません。

## 置き場所の比較

画面が自動で消えないよう、Wake Lock に加えて、無音・真っ黒の小さな動画を見えない所で繰り返し再生しています（ホーム画面に追加した Web アプリでは、iOS 18.4 より前は Wake Lock が効かないための対策）。Wake Lock などを使うため、HTTPS で開ける場所に置く必要があります。

| 方法 | 手間 | 費用 | 公開範囲 |
|---|---|---|---|
| **GitHub Pages**（おすすめ） | GitHubのアカウントが必要。更新は `git push` だけ | 無料 | 無料プランでは公開リポジトリが必要なので、コードもURLも誰でも見られる（URLを知らなければ普通は見つからない） |
| Cloudflare Pages / Netlify | アカウントが必要。ファイルをブラウザでドラッグ＆ドロップして公開できる | 無料 | URLを知っていれば誰でも開ける。コード置き場は非公開にできる |
| iPhone 内のファイルを直接開く | — | — | HTTPS にならず、ホーム画面アプリとしてもうまく動かないため不可 |

どの方法でも APIキーはHTMLに入っておらず中継サーバーにだけあるので、公開してもキーは見られません。公開先を変えたときは、`relay/worker.js` の `ALLOWED_ORIGINS` も新しい公開先に書き換えて、中継サーバーを置き直してください。

## iPhone での使い方

1. iPhone の **Safari** で上のURLを開く。
2. 下の共有ボタン（四角から矢印が出ているアイコン）→「**ホーム画面に追加**」→「追加」。
3. ホーム画面の「元郷 人波時計」から起動する。
4. 左上の「川口元郷」を押して設定画面を開き、歩行時間（秒）を入力して「保存」。

縦向きのときは上り・下りを上下に、横向きのときは左右に並べて表示します（画面を回して表示することはしません）。設定の「上り・下りを入れ替える」をオンにすると、縦向きでは上に下りが来ます。ダブルタップや2本指でのズームはしないようにしています。

ホーム画面に追加せず、ブラウザのまま開いても使えます。アドレスバーなどで使える高さが減る分だけ、カウントの数字を小さくして収めます。

Android では、Chrome でURLを開き、右上の︙メニュー →「アプリをインストール」（または「ホーム画面に追加」→「インストール」）で、ホーム画面からアプリとして全画面で開けます。「ショートカットを作成」を選ぶと、Chrome の画面で開くただのショートカットになります。

スマホ・タブレットのブラウザで開くと（まだインストールしていないとき）、カウント画面を5秒見せてから、インストールの案内が出ます（その間に設定などを開いていれば出しません）。案内は画面全体を覆わない小さめの枠で、後ろのカウント画面が透けて見えます。一番上にアイコンとアプリ名・何のアプリかの一言を出し、「アプリインストールのご案内」として、アプリにすると良いこと（画面いっぱいに表示・ホーム画面からすぐ開ける・電波が弱くても開ける）を絵で見せ、「インストール」ボタンを出します。案内の枠の下にある「次回から表示しない」にチェックすると、次からは出ません。パソコンやホーム画面から開いたときは出ません。設定画面の「アプリ」の枠にある「アプリインストール」の「インストール」ボタンからも、いつでも同じ案内を開けます。

- Android の Chrome: 案内の「インストール」ボタンで、インストールの確認画面が出ます。確認画面を出せないとき（開いた直後でまだ準備ができていない・前に断った など）は、Chrome のメニューからの手順を表示します。
- iPhone の Safari:「インストール」ボタンを押すと、「…」→「共有」→「ホーム画面に追加」→「追加」の手順を、画面の写真付き（`img/ios-step1〜4.jpg`）で表示します（Safari の画面からインストール画面を直接出す仕組みはないため）。iPhone の Chrome などほかのブラウザ用の手順もあります。
- Mac の Safari:「ファイル」→「Dock に追加」の手順を表示します。
- ホーム画面から開いているときは「インストール済み」と表示されます。

Android で「アプリをインストール」が出ないときは、広告ブロックのアプリ（AdGuard など）がページを書き換えていることがあります。そのアプリの許可リストに `kwkmhbk.github.io` を追加し、ページを再読み込みしてください。

画面を表示している間は、自動で画面が消えないようにしています（iOS 16.4 以降。低電力モードでは効かないことがあります）。

## 中継サーバー（Cloudflare Workers）の置き方（PC・最初の1回だけ）

1. Cloudflare（https://dash.cloudflare.com/sign-up ）で無料のアカウントを作る。
2. PC でこのフォルダの `relay` を開き、Cloudflare にログインする（ブラウザが開くので「Allow」を押す）。
   ```
   cd relay
   npx wrangler login
   ```
3. 中継サーバーを置く。最後に表示される `https://kawaguchi-wave-relay.〇〇.workers.dev` のアドレスを控える。
   ```
   npx wrangler deploy
   ```
4. ODPT の APIキーを預ける（聞かれたらキーを貼り付けて Enter）。
   ```
   npx wrangler secret put ODPT_KEY
   ```
5. `index.html` の `RELAY_URL = '';` の `''` の中に、3で控えたアドレスを書いて、GitHub に上げ直す。

キーを変えたいときは4だけ、`relay/worker.js` を直したときは3だけをやり直します。

## 動作確認用のデバッグ機能

URL の最後に `?debug` を付けて開くと、画面の下にデバッグ用の欄が出ます。

- 好きな日時に時計を合わせられます（平日朝・土曜・祝日・日付またぎ・終電後・年末のボタンあり）。
- 遅延情報を「平常」「遅延」「取得失敗」の模擬データに切り替えられます。

## データの提供元

- 時刻表: Mini Tokyo 3D（https://github.com/nagix/mini-tokyo-3d）が公開しているデータ。元は公共交通オープンデータセンター（ODPT）のオープンデータ。
- 運行情報: 公共交通オープンデータセンター（ODPT）の東京メトロ運行情報。
- データの正確さは保証されていません。目安として使ってください。
